# Recent models on a 16 GB M2 Pro, Tier 1 and 2, 2026-11-04

## TLDR

**Verdict:** Not a good fit. No model passed both tiers on this Mac, and the default MiniCPM-V 4.7 itself fails Tier 1 here on memory (6% free against the 10% limit), so nothing beats it and nothing is adopted. Closest: Qwen3.5 9B UD-Q4_K_XL (Tier 1 pass, 21/22 at the 15-minute cap) and Qwen3.6 35B-A3B UD-IQ1_M at 16k (Tier 1 pass, 19/22 in 5.0 min at 43 tok/s).

| Check | Result |
|---|---|
| Tier 1 gate | 5 of 12 runs passed Tier 1 (Bolt E4B, Ornith 9B, Qwen3.5 9B, and the Qwen3.6 16k and Qwen3.5 MTP variants); 7 failed on time, memory, an empty reply or a server error |
| Tier 2 (22 tasks; champion bar 22/22) | Best 21/22 (Qwen3.5 9B, at the cap); then 20, 19, 18, 18 |
| Tier 3 (7 tasks) | Qwen3.5 9B only, one run each (user's request, although it missed 22/22): Go 15, cleaning 21, insight 0, Kanban 2, nursery 90, Mars 95, tax 76 |
| Quality | One run per row; scores differ by a few points and are not findings |
| Time | Tier 2 5.0 to 15.0 min; decoding 23 to 43 tok/s on models that ran |
| Memory pressure | Lowest free 5% to 51%; swap growth up to 1.1 GB per run |

**Against the champion:** MiniCPM-V 4.7 IQ2 passes 5 of 5 gate runs on the 24 GB M4 (22/22, 25 tok/s, 22% free). On this 16 GB M2 Pro its 11.3 GB file plus the 64k KV cache fails Tier 1 on memory (6% free, 845 MB swap growth, 30 tok/s).

## Skipped

- Qwen3.8 Flash Next: smallest full GGUFs are about 70 GB.
- Ternary Bonsai 2 27B: needs PrismML's llama.cpp fork.
- The quants in earlier reports for Ornith 1.5 35B-A3B, Qwen3.6 35B-A3B (IQ2_M, 11.5 GB), Qwen3.6 27B and Qwen3.8 27B (IQ3_XXS, 10.9 GB) exceed this Mac's Metal working set with a KV cache, so smaller quants from Hugging Face were used instead (see table).
- Gemma 4 26B, GLM-4.7 Flash and Devstral Small 2: 12.9 GB or more at the quants tried before; no smaller quant tested.

## Details

- **Context:** models given as a Hugging Face reference ran at pill's generic 32k; MiniCPM ran from its catalog name at 64k. This favours the 64k default less than it hurts it, but the comparison is uneven. The Qwen3.6 35B 16k row is an experiment, not the standard gate.
- **MTP experiment:** `unsloth/Qwen3.5-9B-MTP-GGUF:UD-Q4_K_XL` with `spec-type = "draft-mtp"` decoded at 43 tok/s against 24 without (draft acceptance 0.79 on a late request), and the lowest free memory was 32% against 24%. Tier 2 scored 18/22 at the 15-minute cap against 21/22 for the non-MTP file: faster tokens did not improve the score, and one run each cannot separate the two.
- **Failures worth knowing:** Muse and LFM2.5 UD-Q3_K_XL returned an empty reply (thinking); flint and LFM2.5 Q4_K_M returned HTTP 500 `Compute error` from llama-server within 8 to 13 s.
- **Overlap:** a `go test ./...` run overlapped the first Qwen3.6 35B 32k run (about 22:37 to 22:42), so its 8% free memory may be pessimistic. The 16k rerun ran alone.
- **Cleanup:** every failed GGUF was removed with `pill rm` after its run; the router was stopped with `pill stop --all`.
- **Not tried:** Tier 3 for any other model; MTP for Ornith (no MTP file found); Muse with its DFlash drafter or thinking-off template; smaller quants of Muse, flint and LFM2.5; MiniCPM at 32k.

- The model is strong on landing pages (76 to 95, in 12 to 14 minutes) and weak on anything that needs tool use over many steps: Go 15, data cleaning 21, insight 0, Kanban 2. MiniCPM's 6-run medians on the 24 GB M4 are Go 88, cleaning 90.5, insight 40, Kanban 90, nursery 93, Mars 95, tax 98.
- No swap growth on any task. Run through Pi with the same settings as the Tier 1 and 2 run (`pi:qwen3-5-9b-q4kxl-32k`).
- A first attempt scored 0 in 14 s per task because the router was down (Pi: "Connection error"); those three runs were discarded and re-run.
